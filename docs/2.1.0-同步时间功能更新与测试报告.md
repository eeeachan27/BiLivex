# BiLivex 2.1.0 同步时间功能更新与测试报告

## 一、结论

BiLivex 已完成「同步时间」功能开发，当前正式版本为 `2.1.0`。

按钮位于 B 站直播播放器底部原生操作栏的直播持续时间右侧，直接继承相邻原生图标控件的类名与布局规则。点击后跳到播放器最后一段本地缓冲区的末端前 `0.05` 秒；缓冲区不可用时回退到可拖动区间末端。同步过程仅修改 `video.currentTime`，不会主动播放、暂停、点击原生按钮或阻断原生事件。

功能思路参考 [DouyuEx](https://greasyfork.org/zh-CN/scripts/394497-douyuex-%E6%96%97%E9%B1%BC%E7%9B%B4%E6%92%AD%E9%97%B4%E5%A2%9E%E5%BC%BA%E6%8F%92%E4%BB%B6)；B 站的 DOM 定位、多缓冲分段处理、边界保护、生命周期恢复、原生视觉继承和测试代码均按 BiLivex 的实际结构独立实现。

本轮自动化与真实直播间验证均已通过，用户已完成实机验收并授权发布。脚本已同步 GitHub、GitHub Release、jsDelivr 和 Greasy Fork。

## 二、实现范围

### 2.1 同步目标

1. 优先读取 `video.buffered`，使用最后一段缓冲区而不是第一段缓冲区。
2. 当缓冲区没有可用分段时，回退到 `video.seekable` 的最后一段。
3. 目标位置为最后一段末端前 `0.05` 秒，避免正好落在媒体分段边界导致短暂停顿。
4. `TimeRanges` 在媒体分段刷新期间瞬时失效时，本次点击静默退出，不影响播放器。

### 2.2 原生操作栏接入

1. 以 `#live-player` 内的 `.text.time` 为直播持续时间锚点。
2. 将同步按钮作为时长容器的下一个兄弟节点插入，不包裹、不移动、不替换任何原生节点。
3. 复用相邻原生 `.icon` 控件的完整类名，图标使用 `currentColor`，自动继承原生颜色、悬停和布局样式。
4. 按钮提供 `title="同步时间"`、键盘 Enter / 空格操作和无障碍标签。
5. 根据实机截图重绘图标：外圈视觉边界以 `(12, 12)` 为中心，箭头移到左上方；中心时针缩短，箭头与时针的几何水平间距保持至少 `3.5` 个视区单位。

### 2.3 生命周期兼容

1. 复用 BiLivex 已有的全页面 `MutationObserver`，没有新增第二条全局观察链。
2. 识别 B 站控制栏的延迟挂载和卸载重建，重新挂载时自动恢复按钮。
3. 同一操作栏重复初始化只保留一个按钮。
4. 沿用现有 SPA 换房、同源 iframe 和 20 秒守护检查机制。

## 七、建议的实机验收清单

1. 将本地 `bilive-enhance.user.js` 更新到 Tampermonkey，但不要发布公开版本。
2. 打开普通 B 站直播间，鼠标移入画面，确认圆形同步图标位于直播持续时间右侧。
3. 让画面落后 5 至 10 秒后点击同步按钮，确认立即追到最新画面，且音视频继续正常播放。
4. 暂停后点击同步按钮，确认时间位置更新但仍保持暂停；再次播放后应从最新位置继续。
5. 分别检查普通窗口、网页全屏和播放器全屏，确认按钮无错位、重叠或挤压原生控件。
6. 切换清晰度、隐藏再唤出控制栏、SPA 切换房间，确认按钮会恢复且始终只有一个。
7. 检查播放、刷新、音量、直播时长、画中画、清晰度和全屏等原生控件仍可正常使用。
8. 如有活动房或 `blanc` iframe 房间，再补测按钮位置与同步行为。
